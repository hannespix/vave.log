# Finance contract (2026-10-13)

`createFinanceService(client: SupabaseClient)` exports inferred `FinanceService`. All calls use the acting user's client, never a service-role key. Inputs/outputs are exported from `src/shared/finance-types.ts` and use snake_case. Ordinary lists are bounded to 1,000. The overview loads up to 50,000 time entries in scoped, deterministically ordered pages, failing the whole calculation on missing pages, count changes, duplicate identities or limits. It never returns knowingly partial totals. Separate requests are not a transactional snapshot.

Money is integer minor units (EUR 7500 = EUR 75). Rates are per hour. Tax is basis points (1900 = 19%). Manual quantities support up to four decimal places. Round each line net, then tax, to nearest minor unit with ties away from zero. Time-backed lines compute net from exact minutes × hourly rate / 60; quantity is only a display value and is recomputed from approved time. No currency argument is accepted; workspace currency is frozen at issue.

Invoice draft lines have `time_entry_id:null` for manual/fixed-fee lines. Zero-tax lines require a meaningful `zero_tax_reason` when issued. Drafts may be saved incomplete (empty line array), but valid customer/date references are required. Issuing requires configured company legal name/address/tax identifier, customer name/address, at least one line and valid tax explanations. Issue is explicit and idempotent per draft ID. A retry returns the existing document and does not allocate a new number. Approved billable time is claimed once globally, including after cancellation. Cancellation retries return the existing cancellation document; paid/unpaid is separate from document content.

`Invoice.lines` contains calculated net/tax/total in minor units. `issuer_snapshot`/`customer_snapshot` are null before issue and frozen objects afterward. `cancellation_id` links an original to its correction; `cancellation_of` links the negative document to its original. The original remains `status:'issued'`; payment does not change status. No email delivery occurs.

SQL RPCs (public invoker wrappers, protected private implementations): `finance_save_draft(p_input jsonb)`, `finance_draft_from_time(p_input jsonb)`, `finance_issue_invoice(p_workspace_id uuid,p_id uuid)`, `finance_cancel_invoice(p_workspace_id uuid,p_id uuid,p_reason text)`, `finance_set_paid(p_workspace_id uuid,p_id uuid,p_paid boolean)`, `finance_get_invoice(p_workspace_id uuid,p_id uuid)`, `finance_list_invoices(p_workspace_id uuid)`. They return a JSON object/array matching Invoice. Draft payload rejects unknown keys including status, number, snapshots and totals. No authenticated direct writes to invoices, payment or time-claim tables.

Direct RLS-protected tables: `finance_clients`, `finance_billing_profiles`, `finance_staff_rates`, `finance_project_plans`, `finance_expenses`. IDs/default timestamps are generated by DB. Plans key on `(workspace_id,project_id)`; profiles key on workspace_id. Each tenant relation uses a composite workspace FK. Managers/owners may save clients, rates, plans and expenses; only owners save profile. Estimates are JSON `lines` validated in SQL and support free labels with `user_id:null` for pre-account freelancers. Root can seed these tables directly in its migration under postgres; no auth user required for planning lines. Staff rates always refer to a real membership. Expense input requires `not_time_costed:true` as an explicit anti-double-counting assertion.

Pure math exports: `roundRatio(numerator:number,denominator:number):number`, `hourlyAmount(minutes,rate_minor):number`, `lineTotals(line:InvoiceLineInput):{net_minor,tax_minor,total_minor}`, `salaryHourlyCost(annual_cost_minor,annual_productive_hours):number`, `projectFinancials(plan,entries,rates,expenses):ProjectFinancials`. Null rates mean unknown, never zero; internal billing returns zero revenue. Forecast subtracts already worked minutes from estimated remaining labor, then adds actual costs and remaining expense budget. Date range applies to actual entries/expenses and is always returned by overview; estimates are full-project baseline.

Errors: `FinanceError` with stable `code` in `validation|forbidden|not_found|conflict|missing_configuration|result_limit|database`. Messages are controlled English, no raw SQL/library dumps. SQL domain messages start with `FINANCE_`; service maps them. UI may map error.code to localized labels.
