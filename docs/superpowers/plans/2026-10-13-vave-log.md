# VAVE.LOG Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Independent database and UI work is delegated using dispatching-parallel-agents; root integrates and implements shared services/MCP.

**Goal:** Ein nutzbares, sicher abgesichertes Teamtool mit Supabase und GUI/MCP liefern.
**Architecture:** React/Vite client; shared validated services; Supabase RLS/RPC; stateless Node MCP server and OAuth consent.
**Tech Stack:** TypeScript, React, Vite, Supabase JS, Zod, official MCP SDK, Express, Vitest, Playwright, PGlite.
**Spec:** docs/superpowers/specs/2026-10-13-vave-log-design.md

## Global Constraints
- Keine Service-Role-Schlüssel in App oder MCP; kein unautorisierter Workspace-Zugriff.
- Deutsche UI, VAVE-CD, authentifizierte Schreibzugriffe, keine erfundenen Produktionsdaten.
- Hannes delegiert Produktentscheidungen ausdrücklich; keine wiederholten Freigabe-Gates.

## Review Focus
- Workspace-/Projekt-IDs eines anderen Mandanten müssen auch direkt über PostgREST scheitern.
- Wiederholter Timerstopp darf keine zweite Buchung erzeugen; Mitternacht/DST/Überlänge müssen erklärbar bleiben.
- Abgelaufene Sessions, Netzwerkfehler und fehlende Konfiguration dürfen keinen Speichererfolg vortäuschen.
- MCP darf über manipulierte Origin-/Host-/JWT-Werte keine Rechte erlangen.
- Lange Namen/Notizen, CSV-Formeln, mobiles Layout und OAuth-Weiterleitungen sicher behandeln.
